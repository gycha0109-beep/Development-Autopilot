활동 기록 및 승인 요청

자동 진행 상태, 사용자 개입 요청, 전체 기록을 확인합니다.

Chrome 관찰 기반 자동 진행

먼저 연결된 작업축의 읽기 관찰을 허용하십시오. 다음 Chrome 동기화 후 관찰 결과가 표시됩니다. 자동 진행은 기존 메시지·기간·횟수 승인을 설정한 뒤 별도로 켭니다. 초안·불명 상태에서는 전송하지 않습니다.

사용자 개입 Inbox

요청을 확인하고 해당 작업축에서 조치하십시오. 메신저는 연결되지 않았습니다.

고급 설정

CI, GitHub 검증, 실행 시뮬레이션 및 ChatGPT 전송 승인을 관리합니다.

CI Watchtower — 읽기 전용 관측

Watchtower v0.3.39+의 전용 Windows Credential Manager 토큰으로 로컬 브리지를 조회합니다. CI 성공만으로 실행을 허가하지 않습니다.

브리지 상태조회 대기Watchtower 프로세스가 실행되어 있어야 합니다.
최종 확인-상태 확인 주기 45초 · 원격 API 추가 호출 없음

정확한 Run 관측 대상 지정

저장소 ID·Run ID·40자리 Head SHA·Attempt를 입력합니다. Watchtower 브리지의 과거 성공 결과를 현재 PR 완료로 판단하지 않습니다.

GitHub PR 사실 검증

GitHub CLI 인증을 사용해 PR Head SHA, 병합 여부, 필수 체크와 브랜치 정책을 독립 검증합니다. 정보가 부족하면 자동 진행을 승인하지 않습니다.

GitHub 검증아직 조회하지 않음 GitHub CLI 로그인 필요 · Watchtower PAT와 별도
마지막 확인- 2분 간격 관측 · 읽기 전용

정확한 PR 지정

PR 번호와 예상 Head SHA를 함께 등록합니다. SHA가 달라지면 다시 승인할 수 있도록 상태를 보류합니다.

통합 의사결정 게이트

Watchtower 관측 · GitHub PR 검증 · 로컬 정지 상태 · 작업 버전을 결합합니다. 검증 근거 확인은 코딩 실행이나 페이즈 완료 승인이 아닙니다.

정책 Fail closed · 실행 승인 분리 불일치·오래된 데이터·필수 체크 불명은 자동 진행 금지
최종 상태 평가 대기 사람 확인은 15분 유효 · 실제 AI 실행 미구현

판단 이력

관측 근거 또는 상태가 달라질 때만 기록하며 개인정보·토큰은 기록하지 않습니다.

Phase 4 — 승인된 단일 작업 실행 시뮬레이션

작업축을 모의 실행 모드로 설정하고 작업 준비를 완료한 뒤, 정확한 계획에 대한 별도 승인을 받아 실행합니다. AI 서비스 호출은 없습니다.

접수(accepted)는 완료가 아닙니다. 실행 후 별도 결과 확인에서 Operation ID·요청 지문·검증 마커를 비교합니다. 결과가 불확실하면 재전송하지 않습니다.

ChatGPT 대화 이어가기 · 새 대화 시작

등록된 기존 대화, ChatGPT 새 채팅 또는 프로젝트 새 채팅에서 승인된 메시지를 보냅니다. 새 대화가 생성되면 변경된 탭 URL을 수동 재연결해야 다음 전송이 가능합니다. Codex CLI·별도 API 키는 사용하지 않습니다.

10분과 예시 메시지는 플레이스홀더일 뿐이며 자동으로 설정되지 않습니다. 두 값을 직접 입력해야 승인됩니다. 전송 전에 등록된 ChatGPT URL(기존 대화·새 채팅·프로젝트 새 채팅), 빈 입력창, 생성 중 여부, STOP 및 CI·PR 검토 상태를 확인합니다. 새 대화가 생성되어 URL이 바뀌면 다음 전송 전 확장에서 '새 주소로 연결'을 눌러야 합니다. 페이지 변경이나 확인 불가 시 전송하지 않습니다. 발송 여부는 확인하지만 AI 응답 완료는 판정하지 않습니다.

정확한 Track·PR·SHA·Run·Attempt의 최신 관측이 필요합니다. 병합 권한을 부여하지 않습니다.

CI 관측·GitHub PR 검증·실제 ChatGPT 메시지 전송은 각각 별도 검증 및 승인 절차를 사용합니다.

시뮬레이터의 검증 성공은 실제 계정에서의 동작을 증명하지 않습니다.
