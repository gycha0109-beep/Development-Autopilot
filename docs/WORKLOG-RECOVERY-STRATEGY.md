# WORKLOG 중심 진행 및 3단계 이관 (2026-11-07)

## 일반 진행과 단위작업
- 실행 전에 해당 저장소/브랜치의 현재 트랙과 연관된 WORKLOG(워크로그) 및 ROADMAP(로드맵)을 실제 파일 검색으로 확인합니다.
- 파일명은 고정하지 않습니다. `docs/operations/*WORKLOG*`, `docs/**`, 트랙별 문서 등 실존하는 경로를 살피고 최신 관련 문서와 현재 코드, PR, CI를 대조합니다.
- **매 작업 단위 종료 시** 기존 트랙별 WORKLOG를 갱신하고 코드 변경과 함께 커밋합니다. 기존 문서가 없다면 `docs/operations/<TRACK>_WORKLOG.md`를 새로 만들 수 있습니다.
- 로그에는 작성 일시, 대상 트랙, 브랜치/HEAD, 작업 목표, 변경한 파일, 실제 완료 사항, 미완료/WIP, 테스트·CI 근거, 블로커, 다음 작업을 기록합니다. 검증되지 않은 내용은 `미확인`으로 표시합니다.
- 승인이 필요한 배포, 병합, 결제, 파괴적 데이터 변경은 승인 없이 실행하지 않습니다.

## 자동 이관 우선순위
| 우선 | 이관 근거 | 전환 조건 |
|---|---|---|
| 1 | 원본 채팅에 이관문 작성 요청, 실제 생성된 원문 + WORKLOG/ROADMAP | 원본에서 단 1회 송신을 시도하고 검증된 본문을 확보 |
| 2 | 마지막 **검증된 완료 응답 1개** + WORKLOG/ROADMAP | 1단계 요청이 클릭되지 않은 것이 확실하거나, 작성 후 장시간 응답이 없고 실제 길이 제한 경고를 재확인 |
| 3 | **WORKLOG/ROADMAP만** + 코드/PR/CI | 2단계 마지막 응답 검증이 16초 이상 간격의 경과 및 동일 실패 3회로 계속 불가능함을 확인 |

3단계는 이전 채팅 내용을 알고 있다고 주장하지 않고 `partialContext`를 남깁니다. 대상 채팅은 *해당 트랙의 최신 문서 위치를 먼저 찾아 구현 상태를 검증*한 뒤에만 작업을 재개합니다.

## 전송 안전 규칙
- 1단계 요청은 **한 번만** 시도합니다. 클릭/폼 제출 여부가 불명확하면 정지하며 재전송하거나 다음 단계로 넘어가지 않습니다.
- 전송되지 않은 것이 확인된 편집기·전송 버튼 실패에서만 2단계로 넘어갑니다. 미전송 초안이나 권한 팝업은 덮어쓰지 않습니다.
- 2단계 응답이 생성 중이면 3단계로 넘어가지 않습니다. 3단계로 넘어갈 때 원본 응답/결정을 임의 생성하지 않습니다.
- 이관 과정의 원본 메시지·새 채팅 전송·제목 변경·등록 갱신은 각 한 번만 수행하며, 대상에서 답변 및 연결이 검증되기 전에 자동 실행을 재개하지 않습니다.
- Chrome Manifest V3의 `chrome.storage.session`은 확장 프로그램을 다시 로드하면 사라지므로, **실행 중 이관이 있으면 무작정 재로드하지 않습니다.** 업데이트 시에는 이관 완료 후 적용하거나 별도의 검증된 복원 절차가 필요합니다.

## 작업로그 기본 항목
```markdown
## [날짜/시간] 트랙명 — 작업 단위
- 브랜치 / HEAD / 관련 PR:
- 목표 및 범위:
- 변경 파일:
- 완료한 구현:
- 테스트 / CI (실제 실행 근거):
- 미완료·차단 요인:
- 다음에 바로 할 작업:
- 승인 필요 사항:
```

파일 경로가 다르거나 WORKLOG와 ROADMAP 간 내용이 충돌하면 실제 최신 코드·테스트 근거를 우선하며 문서 불일치를 보고합니다.
