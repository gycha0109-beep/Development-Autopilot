# 개발 대화 이관 — 로드맵 기반 복사 → 프로젝트 새 채팅

Chrome 확장 v0.4.6 / composer r7. 현재는 단계별 버튼으로 실행하며, 이관 텍스트와 대상은 사용자가 직접 검토·승인합니다.

## 이관 순서

1. 원본 기존 대화와 대상 프로젝트 새 채팅을 각각 Chrome 그룹·탭으로 등록합니다.
2. 확장 옵션의 이관 섹션에서 두 등록 탭, 기존 대화 제목(숫자 포함), GitHub 저장소를 지정합니다.
3. 1번 버튼을 눌러 로드맵 기반 이관문 작성을 원본에 1회 요청합니다. 로드맵이 없으면 작성·보완이 필요하다고 명시하도록 요청합니다.
4. 새 assistant 답변이 완성된 후 2번 버튼으로 마지막 이관 답변만 가져옵니다. 응답 시작 표식 확인 후 최대 30,000자를 저장합니다.
5. 이관문을 직접 검토·수정할 수 있으며 클립보드 복사 버튼도 있습니다. 수정 시 내용 저장 후 전송합니다.
6. 3번 버튼을 누르면 승인된 대상 프로젝트 새 채팅에 첫 메시지로 내용을 전송합니다.
7. 새 대화가 생성되면 프로젝트 식별자를 확인하고 응답이 최소 6초 동안 안정된 다음 제목 변경을 시도합니다.
8. 제목은 기존 제목의 마지막 숫자에 1을 더합니다. 자동 제목 변경 UI를 찾지 못하면 직접 변경 후 확인 버튼을 눌러야 합니다.
9. 5번 버튼으로 같은 프로젝트에 생성된 신규 대화 URL을 해당 등록 탭에 재연결합니다. 그 후 해당 작업축의 후속 지시를 별도 승인하여 계속 진행합니다.

## 중요한 제한

- 길이 제한 경고가 이미 표시되어 기존 대화에서 더 이상 메시지를 보낼 수 없다면 이관 요청도 차단될 수 있습니다. 이 경우 이전에 작성해 둔 이관문을 직접 입력할 수 있으며, 확장이 없는 답변을 만들어내지는 않습니다.
- 본문은 Chrome storage.session에만 임시 보관하며 대상 전송 시 지웁니다. 로컬 서버로 ChatGPT 대화 본문을 업로드하지 않습니다.
- 명시적 버튼·탭 선택·localhost 페어링·전체 STOP 검사를 통과해야 실행합니다.
- 오발송, 다른 프로젝트 이동, 기존 사용자의 초안, 길이 제한, 수신 불명 상태에서는 자동 재전송하지 않습니다.
- 자동 제목 변경은 ChatGPT UI가 유일하게 식별되는 경우에만 시도합니다. 첫 출력 완료 이전에는 절대 제목을 수정하지 않습니다.
- 실제 Chrome 프로젝트 채팅에서 이관 및 제목 메뉴는 아직 Windows 실기기 검증이 필요합니다.
- Codex CLI나 별도 API 토큰은 사용하지 않습니다. 기존 일반 자동 전송의 주기와 문구는 변경하지 않습니다.

## Windows 실행

git fetch origin
git switch --track origin/feat/chat-migration-handoff
npm.cmd run check

실행 중인 npm.cmd start는 Ctrl+C로 종료 후 다시 npm.cmd start로 실행합니다. Chrome 옵션 탭을 닫고 확장을 새로고침한 다음 새 옵션 페이지를 여십시오.
버전 0.4.6 / composer r7 확인 후 이관 섹션을 이용합니다. 기존 주기 자동 전송은 먼저 중지하고 테스트하는 것이 안전합니다.
