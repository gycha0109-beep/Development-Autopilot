# Windows Acceptance — ChatGPT 새 대화 / 프로젝트 새 채팅

## 배경

기존 확장은 chatgpt.com/c/{id} 및 chatgpt.com/g/{gpt}/c/{id}처럼 이미 생성된 대화 URL만 허용했습니다. 새 채팅 첫 화면(chatgpt.com/)과 프로젝트 첫 화면(chatgpt.com/g/g-p-{project}/project)은 NOT_EXISTING_CHATGPT_CONVERSATION으로 차단되었습니다.

## 새로 지원하는 URL

- 기존 대화: /c/{id}, /g/{id}/c/{id}
- 완전히 새 채팅: /
- 프로젝트 새 채팅: /g/g-p-{project}, /g/g-p-{project}/project

프로젝트 외 일반 커스텀 GPT 홈, 검색, 설정, 파일 화면은 계속 차단합니다. 승인된 메시지 전송은 기존의 빈 입력창·정확히 1개 편집기·전송 버튼/폼·생성 중 아님·대화 이동 없음·작업축/CI 게이트를 모두 통과해야 합니다.

## 실기기 테스트

1. PowerShell: git fetch origin; git switch --track origin/feat/chat-new-and-project-conversation
2. 기존 npm.cmd start 서버를 Ctrl+C로 중지 후 npm.cmd start 재실행.
3. Chrome 확장 관리 탭을 닫고 chrome://extensions에서 확장 새로고침, 새 관리 화면 열기.
4. 버전 0.4.5 및 composer-2026-10-13-r6 확인.
5. Chrome에서 ChatGPT 새 채팅 첫 화면 또는 프로젝트 첫 화면을 엽니다. 프로젝트 홈에는 입력창이 실제로 보이는지 확인합니다.
6. 해당 탭을 Chrome 그룹에 넣고 확장에서 그룹 등록 → 탭 등록 → 지금 동기화합니다. 기존 작업축과 연결합니다.
7. 확장 관리 화면의 '진단할 등록 ChatGPT 탭'에서 대상 탭을 선택한 뒤 읽기 전용 진단을 실행합니다. 화면 유형이 '새 대화' 또는 '프로젝트 새 채팅', 편집기 후보 1개인지 확인합니다. 등록된 탭이 여러 개라도 개별 선택할 수 있습니다.
8. **수동 1회**, 최대 전송 1회, 간단한 첫 메시지로 승인 → 지금 1회 보내기.
9. 첫 메시지가 정확한 프로젝트 안에 생성되는지 확인합니다.
10. 새 대화가 생성되면 URL이 바뀌므로 확장에서 '새 주소로 연결' 클릭 → 지금 동기화. 그 전에는 후속 메시지가 자동 전송되지 않아야 합니다.

## 안전·제한

- 새 대화 첫 전송도 기존 승인·STOP·실행 중 차단·중복 방지 규칙을 따릅니다.
- 기존 blocked 명령은 재시도하지 않습니다.
- 페이지가 메시지 입력 도중 이동하면 전송하지 않습니다.
- 첫 메시지 전송 클릭을 'sent'로 기록하지만 ChatGPT 서버 응답/대화 생성까지 보장하지는 않습니다.
- 실제 프로젝트의 DOM/URL이 위 패턴과 다르면 임의로 우회하지 말고 진단 결과와 주소 경로를 보고 추가합니다.
- 현재 메시지 최대 길이는 800자입니다. 긴 이관 프롬프트 지원은 별도 작업입니다.
