# Development Autopilot — 채팅 중심 관제 / 작업축 선택화

기준: 2026-11-01. PR #97 (기반 PR #96). 현재 코드는 개발 브랜치에서만 검증하며 운영본에는 설치하지 않습니다.

## 사용자 작업 흐름

Chrome 팝업에서 **ChatGPT 채팅 선택 → 채팅 매크로 설정 → 자동 진행**으로 진입합니다. Chrome 탭 그룹이나 작업축을 반드시 만들 필요가 없습니다. 기존 그룹·작업축 자동화도 고급 호환 기능으로 유지합니다.

관리 화면에는 채팅과 매크로·연결·복구 상태를 우선 표시합니다. 일반 진행 매크로가 기본이고, CI 실패·로드맵 완료·사용자 승인·네트워크 오류·연결 해제·대화 길이제한을 별도 상황으로 구분합니다.

## 자동 복구와 전송

- **일반 진행:** 실제 ChatGPT 완료 응답의 동일성·안정성·입력창 상태를 두 번 검사하고 최소 전송 간격을 지켜 전송합니다.
- **CI 레드:** 선택한 저장소의 GitHub 실패 Run ID, Attempt, HEAD SHA, 신선도와 열린 CI 이상 사건이 일치할 때만 CI 원인 분석 매크로를 선택합니다. CI 결과 자체는 자동 승인·병합 근거가 아닙니다.
- **로드맵 보고:** 완료 상황이 검증되면 현황 보고 매크로로 전환하고 이후 일반 진행으로 돌아갑니다.
- **승인·블로커:** 필요한 정보와 승인 절차를 기록하고 자동 전송을 멈춥니다. 사용자 승인을 추정·자동 클릭하지 않습니다.
- **네트워크 오류:** 검증된 경고에 한해 제한적으로 복구 조작하고 새 완료 응답의 안전성을 다시 확인합니다. 5회의 제한적 관측 후 불가능하면 개입을 요청합니다.
- **연결 해제:** 동일 URL·정확한 세션 키/창/탭 신원으로 재연결을 관찰합니다. 새 URL을 임의로 같은 채팅으로 취급하지 않습니다.
- **길이제한(프로젝트 채팅):** GitHub 저장소가 선택되고 정확한 프로젝트/숫자 제목이 검증되면 기존 이관 워커로 동일 탭의 다음 채팅에 인계합니다.
- **길이제한(일반 채팅):** GitHub 저장소·작업축·Chrome 그룹 없이, 기존 `/c/...` 채팅에서 시스템 길이 경고를 확인합니다. 완료된 이전 응답 또는 원본 채팅에서 작성한 이관 문서를 사용해 새 `/c/...` 채팅에 전달합니다. 새 채팅의 실제 인계 사용자 메시지·첫 완료 응답을 확인하고 같은 등록 세션에 연결한 후 자동 진행을 재개합니다. 원본이 이미 제한 상태라면 **검증된 마지막 어시스턴트 응답만** 사용하며, 전체 대화를 복원했다고 주장하지 않습니다.

기존 작업축의 전송과 새로운 매크로 전송은 **동일한 실제 ChatGPT 탭 검증·전송 처리**를 사용합니다. 단, 별도 SQLite 기록과 승인 판정은 이전 사용자 데이터를 보존하기 위해 그대로 유지합니다.

## 안전 계약

- 전체 자동화 정지 상태에서 새 작업·이관·복구 부작용을 실행하지 않습니다.
- 전송 직전 연결된 확장 프로그램, 승인된 채팅 URL/탭, 최신 관측 증거, 입력창, 등록 상태를 다시 확인합니다.
- 응답 완료 판정이 불충분하거나 사용자 승인·UI 오류·제한이 있으면 자의적으로 다음 프롬프트를 보내지 않습니다.
- 전송 또는 이관이 실제 수행됐는지 모호하면 **중복 발송하지 않고** 해당 채팅만 개입 필요 상태로 변경합니다.
- 일반 채팅 이관은 실제 이전/새 채팅의 사용자·어시스턴트 메시지 신원을 입증할 수 있는 경우에만 자동 완료합니다. DOM 구조가 바뀌어 증거가 없으면 완료 판정하지 않습니다.
- Telegram 자동 알림은 `AUTOPILOT_TELEGRAM_ENABLED=1` 및 `AUTOPILOT_MACRO_ALERTS_ENABLED=1`을 모두 명시적으로 설정한 환경에 한합니다. 실제 수신 시험은 아직 미완료입니다.
- 기존 Workstream 설정과 GitHub PAT/인증 저장소, WatchTower SQLite 데이터는 수정하지 않습니다.

## 검증 및 남은 완료 조건

구현 검증에는 일반 채팅의 그룹 없는 등록/백업/재시작 복구, 공통 전송 경로, 프로젝트/일반 채팅 자동 이관 모의 실행, 오류 시 중복 재전송 금지, CI 근거 확인, Telegram 가짜 전송, 전체 정지 유지가 포함됩니다.

**실제 ChatGPT DOM 관통 검증**(일반 진행·네트워크 오류·이관)은 별도로 필요하며, 자동 테스트 PASS만으로 완료라고 보고하지 않습니다. Chrome 서비스 워커 재기동 시 이관 증거가 불완전하면 사용자 개입이 필요할 수 있습니다.

PR #96의 운영 반영·실제 Telegram 수신·사용자 승인 후 재개·WatchTower 상시 실행 제거·BuildMap 읽기 전용 CI 연동도 **별도 미완료 과제**입니다.

운영 프로그램 전체 정지는 승인 전까지 해제하지 않습니다. PR 병합·운영 배포·실제 ChatGPT 메시지 전송·Telegram 발송은 별도 승인 없이는 실행하지 않습니다.
