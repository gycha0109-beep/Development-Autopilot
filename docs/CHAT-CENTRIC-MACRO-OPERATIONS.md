# Development Autopilot — 채팅 중심 상황별 매크로 전환

작성: 2026-11-01. 기반: PR #96, 확장 프로그램 0.4.47, 서버 0.8.1.

## 목표와 범위

작업축(Workstream)을 만들지 않아도 **열려 있는 ChatGPT 채팅을 선택하고 상황별 매크로를 설정**할 수 있습니다. 기존 작업축/CI 판정/Telegram/Chrome 기능은 삭제하지 않고 고급 호환 기능으로 유지합니다.

Chrome 확장 프로그램의 빠른 실행 창에서 채팅을 선택하고 **채팅 등록 및 매크로 설정**을 누릅니다. 등록되지 않은 기존 ChatGPT 채팅은 기존 등록 절차를 호출해 등록합니다. 저장할 매크로를 선택해 내용을 수정할 수 있으며, **선택 매크로 1회**로 수동 전송할 수 있습니다.

## 매크로

| 이름 | 기본 동작 | 자동 감지·대응 |
| --- | --- | --- |
| 일반 진행 | 로드맵 다음 작업 계속 | 완료 응답 2회 확인, 30초 안정성 및 최소 전송 간격 검증 후 |
| 로드맵 현황 보고 | 완료·남은 단계·다음 작업 보고 | 단계 완료 신호를 감지하면 한 번 선택 |
| CI 레드 | 정확한 실패 Run/Attempt/SHA 조사 | GitHub 근거가 없는 채팅은 자동 실행하지 않음, 수동 선택 가능 |
| 블로커·승인 | 원인, 승인 필요 사항, 절차 정리 | 사용자 개입 감지 시 자동 전송 일시 중단, 매크로 수동 선택 |
| 네트워크 오류 | 재시도 제한·복구 안내 | 연결 오류 감지 시 전송 일시 중단 |
| 연결 해제 | 연결 상태·복구 안내 | 기존 채팅 식별 정보가 같으면 재접속을 기다리고, 변경되면 재승인 필요 |
| 채팅 길이제한·이관 | 이관 문서 생성 요청 | 길이제한 감지 시 자동 전송 중단, 이관은 검증 후 수동 승인 |

**주의:** 이 단계는 상황 감지·실패 차단·사용자 직접 선택이 중심입니다. 자동 이관, 정확한 외부 CI 레드 트리거, 네트워크 복구 후 재전송은 모두 아직 완전 자동화하지 않았습니다. 전송 결과가 불명확하거나 답변에 사용자 승인이 필요하면 반복 전송하지 않습니다.

## 전송 안전장치

- 전체 자동화 정지가 켜져 있으면 새 매크로 전송/전송 대기열 수령을 거부합니다.
- 등록된 실제 ChatGPT 탭, 정확한 URL 식별 정보, 연결된 확장 프로그램 및 입력창 버전을 확인합니다.
- 30초 이상 간격의 최신 완료 응답 확인 2회와 응답 지문 일치를 요구합니다. 수동 전송도 정확한 탭과 로컬 서버 확인을 통과해야 합니다.
- 이전 응답에 대한 중복 전송, 완료되지 않은 메시지, 막힌 CI, 중대한 UI 오류는 자동 진행 대상이 아닙니다.
- 확장 프로그램 재페어링, 다른 대화로 변경, 기존 작업축과 동일 탭 충돌, 전송 결과 불확실 또는 재시작 후 미확정 명령은 자동 전송을 중단합니다.
- 매크로 저장은 확장 프로그램에 연결된 로컬 SQLite에 보존됩니다. 새 매크로는 별도 동의 전에는 운영 서버의 기존 설정과 섞지 않습니다.
- '매크로 전송 요청 등록'은 실제 ChatGPT 수신 또는 응답 성공을 의미하지 않습니다. 확장 프로그램의 실행 확인 결과를 별도로 점검합니다.

## PR #96 잔여 과제 — 별도 완료 조건 유지

1. PR #93 → #94 → #95 → #96 변경 계보, Windows/Ubuntu CI 및 사용자 승인 사항 확인. PR #96의 GitHub 자동 CI와 Windows 격리 시험은 통과했지만 운영 반영은 아직 하지 않았습니다.
2. 기존 집 PC 운영 SQLite와 설치 코드의 최신 백업 및 복구 경로 검증.
3. PR 병합 또는 운영 설치본 갱신 승인 후 배포, 운영 재시작 및 상태/Chrome/Telegram/DB 무결성 확인.
4. 별도 시험 환경에서 Telegram 실제 알림 1회, 중복 억제 및 복구 알림 검증(승인 및 비밀 관리 전제).
5. 실제 사용자 작업의 실패/대기/승인 후 후속 판단을 검증하면서 전체 자동화 정지는 별도 승인 전 유지.
6. WatchTower 프로세스가 꺼진 상태에서 독립 관제·알림·재개를 검증한 뒤에만 WatchTower 상시 시작 설정을 제거합니다.
7. BuildMap에는 관측/판정 읽기 계약을 재사용하며 CI 이력의 불완전한 성공을 작업 승인으로 해석하지 않습니다.
