# Development Autopilot — 채팅 중심 자동 관제 및 매크로 인수 기준

기준: 2026-11-01 / Autopilot 0.8.2 / Chrome 확장 0.4.48 / 선행 PR #96.

## 목표

등록된 ChatGPT 채팅을 관제의 기본 단위로 사용합니다. 작업축은 선택 기능입니다. **작업축이 0개인 상태에서 채팅 매크로 설정, 자동 완료 감지, 네트워크·연결 복구, CI 이상 대응 및 자동 이관의 프로젝트 채팅 경로가 작동**하도록 구현했습니다.

관리 화면의 첫 영역에 채팅별 연결·매크로·복구 상태가 나타납니다. 기존 작업축 관리 영역은 고급 기능으로 남겨 운영 데이터와 기존 호환 경로를 보존합니다. Chrome 팝업에서 채팅·매크로를 직접 설정합니다.

## 상황별 자동 처리

| 매크로 | 조건 | 처리 |
| --- | --- | --- |
| 일반 진행 | 안전한 완료 응답을 2회 확인, 30초 안정화 | 기본 프롬프트 1회 전송 |
| 로드맵 현황 보고 | 작업 완료 신호 + 안전한 완료 응답 | 로드맵 보고 요청 후 일반 진행 복귀 |
| CI 레드 | 사용자가 채팅에 지정한 정확한 저장소의 최근 실패 Run·Attempt·SHA가 독립 관측 및 열린 이상 기록과 일치 | CI 실패 분석 매크로로 자동 분기; CI 성공만으로 배포·병합·승인 허용하지 않음 |
| 승인·블로커 | 사용자 승인/외부 제한의 명확한 신호 | 작업 전송 중단, 상태 기록, 별도 동의 시 Telegram 알림. 승인 자동 클릭 금지 |
| 네트워크 오류 | 검증된 ChatGPT 통신 경고 | 자동 복구 상태, 안전한 경우 기존 검증 절차로 중단 제어 1회, 최대 5회 간격 재관측, 복구 확인 시 네트워크 복구 매크로; 실패 시 알림·수동 개입 |
| 연결 해제 | 정확한 동일 채팅의 탭 연결 끊김 | 기존 Chrome 등록 복구·동일 URL 재연결 확인 후 연결 복구 매크로. URL이 변경되면 자동 재승인 금지 |
| 채팅 길이제한·이관 | 검증된 길이제한 경고 | **저장소가 지정된 ChatGPT 프로젝트 채팅이고 제목이 숫자 트랙 형식이면** 기존 검증된 이관 워커로 문맥 인계·새 대화 연결·제목 확인 후 자동 복귀. 조건 불충족/실패 시 상태 기록·사용자 개입 요청 |

네트워크·연결 복구는 오류를 이유로 과거 메시지를 무조건 재전송하지 않습니다. 이미 발송했는지 알 수 없는 메시지는 영구 보류하고 수동 확인을 요청합니다.

## 안전 계약

- 전체 자동화 정지 활성 시 신규 메시지, 네트워크 복구 조작, 이관 작업을 시작하지 않습니다.
- 자동 발송은 정확한 등록 채팅·확장 버전·URL 지문·안전한 입력창·최근 응답 지문과 두 번의 완료 관측을 필요로 합니다.
- GitHub CI 실패는 최신 관측(5분 이내)과 최근 실패 실행(3시간 이내), 정확한 저장소·Run ID·Attempt·SHA·이상 감지 사건이 모두 일치해야만 분석 매크로를 선택합니다. CI 판정은 어디까지나 조사 요청이며 PR 병합·실행 승인 근거가 아닙니다.
- 네트워크 복구의 UI 조작은 해당 세션에 대한 사전 승인 후 정확히 한 번만 시도합니다. 결과가 불확실하면 반복하지 않습니다.
- 기존 작업축과 동일 채팅의 이중 자동 제어를 차단합니다. Workstream 저장소/설정/승인 데이터와 WatchTower SQLite 쓰기 경로는 그대로 유지합니다.
- 사용자가 승인하지 않은 Telegram 발송은 하지 않습니다. **AUTOPILOT_TELEGRAM_ENABLED=1 및 AUTOPILOT_MACRO_ALERTS_ENABLED=1을 모두 설정한 경우에만** 기존 Windows 안전한 인증 저장소를 이용해 자동 알림을 발송합니다. 중복 억제·일일 상한·미확인 응답 재발송 금지가 적용됩니다.
- 사용자 승인이 필요한 실제 도구 사용, PR 병합, 배포, 전체 정지 해제는 자동으로 수행하지 않습니다.

## 미완료·실환경 확인이 필요한 사항

1. 실제 ChatGPT DOM에서 자동 진행, 네트워크 복구, 연결 해제, CI 레드 분기 및 이관까지 독립 실기기 검증.
2. 작업축이 없고 GitHub 저장소를 연결하지 않은 **일반 ChatGPT 채팅**의 완전 자동 이관은 아직 지원하지 않습니다. 해당 조건을 검증하지 않고 완료로 보고하지 않습니다.
3. Telegram 실제 테스트 수신과 사용자 승인 후 재개 검증(시험 계정/채널, 별도 동의 필요).
4. PR #93 → #94 → #95 → #96 → 현재 매크로 PR의 병합 순서 확인, Windows·Ubuntu CI 통과, 백업 후 운영 배포 및 재시작 검증.
5. WatchTower 상시 실행 등록 제거와 CI 독립 관제 최종 운영 검증, BuildMap에 읽기 전용 근거 계약 연결.

## 운영 원칙

현재 PR은 기존 운영본에 설치되지 않았습니다. 집 PC 운영 Autopilot은 전체 자동화 정지를 유지하며, 별도의 PR 병합·운영 배포·실제 채팅 전송·Telegram 발송은 승인 전까지 수행하지 않습니다. 기존 PR #96의 나머지 운영 인수 과제는 이번 매크로 PR로 인해 완료 처리하지 않습니다.
