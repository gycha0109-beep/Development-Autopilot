## 구현한 운영 경로

기존 `DisconnectRecovery`를 운영 coordinator 및 확장 worker에 연결했다.
기존 SQLite operations, 단계 ledger, 승인·관찰·CI 결정기와 정상 전송 큐를 재사용한다.
모든 기존 작업축은 복구 권한이 기본적으로 꺼져 있다.

1. 신선한 정상 관찰과 유효한 기존 예약 전송 승인이 있는 작업축에 한해 관리 화면에서
   **중지 1회 + 고정 현황 보고 요청 1회**를 별도로 허용한다. 기존 계속 진행 횟수·기간은 늘리지 않는다.
2. 두 관찰에서 실제 연결 해제 경고가 지속되고 중지 컨트롤 소속이 확인되면 Stop intent를 먼저 기록한다.
3. 새 worker 프로토콜, 등록된 물리적 탭·그룹·session epoch, 승인·초안·경고를 재검사한다.
   서버의 실행 직전 허가 뒤 같은 대화의 유일한 중지 버튼을 한 번 클릭한다.
4. worker ACK와 이후 읽기 전용 중단 확인을 분리한다. 중단 확인 후에만
   `현재까지 진행한 작업과 남은 작업을 보고해줘.`를 기존 전송기로 한 번 보낸다.
5. 새 사용자 메시지 ID의 지문과 정확한 고정 문구를 확인해야 제출 ACK가 성립한다.
   이후 별도 요청의 관찰에서 같은 사용자 지문·Operation ID에 속한 새 assistant 응답을 확인한다.
6. 두 안정 표본으로 보고 응답 완료를 검증하고 기존 결정기로 재판단한다.
   CI 대기·사람 개입·길이 제한은 각각의 기존 분기로 간다. 계속 진행은 기존 승인·횟수·중복 차단을 다시 통과해야 한다.

초안, 제한, 모호한 버튼, 전송 여부 불명, 허가 철회, 재시작 중 미확인 intent는 자동 재시도하지 않는다.
해당 작업축을 Inbox 대기로 보낸다. 완료한 복구 에피소드 후 같은 축에서 다시 연결 오류가 발생하면
추가 Stop/보고 없이 사람을 호출한다. 활성 복구 중에는 자동 이관의 쓰기를 거부한다.
관찰 원문·초안·사용자 메시지 ID는 서버에 저장하지 않는다.

서버의 전체 tick은 브라우저 응답을 기다리지 않는다. 작업축별 in-flight 잠금과 공정 큐로
중복 검사를 막으면서, 한 축의 Stop ACK 대기가 다른 축의 다음 관찰·전송을 막지 않도록 했다.
`/api/v1/tick` 응답은 감시 시작을 뜻하며 완료 여부는 snapshot/ledger에서 확인한다.

기존 DB의 recovery 큐 기본 lease 90초는 정확한 이전 기본 정책이고 진행 중/대기 작업이 없을 때만
330초로 올린다. 사용자 지정 정책과 활성 작업은 거부하며 next-start·작업 이력·승인·등록은 유지한다.

## 실제 Windows Chrome에서 확인한 것

2026-10-21 실제 Windows Chrome의 원래 `codex_ci_recovery` 대화는 정상 본문과 빈 입력창을 표시했다.
기존 CI/Inbox 테스트 응답과 전송 기록이 남아 있다. 사이드바의 기록 로딩 오류와 정상 대화 본문을 구분했다.
이 대화에는 실제 연결 해제 경고/Stop 버튼이 없으므로 새 복구 성공을 주장하지 않는다.

기존 `.autopilot/acceptance.sqlite3`를 백업한 뒤 서버를 다시 기동했다.
기존 5개 작업축·5개 연결·6개 전송 기록을 삭제하지 않았다. 새 복구 권한은 부여하지 않았다.
실제 서버에서 발견한 큐 정책 업그레이드 기동 오류를 수정하고 같은 DB 기동을 확인했다.

서버 기동 직후 확장은 2026-10-20 마지막 동기화의 offline 상태였으나 이후 실제 heartbeat가 돌아와 online을 확인했다.
등록 세션은 missing/needs-rebind이고 후보는 0개이며 새 복구 worker의 실행은 아직 확인하지 못했다.
실제 확장 경로는 `D:\cha\Development-Autopilot\extension`이다. 설치 소스 전체가 검토된 0.4.38
커밋 `595137f`와 일치함을 확인하고 백업한 후 0.4.40 소스 22개 파일을 적용·해시 비교했다.
별도 체크아웃의 브랜치와 확장 저장소·페어링은 바꾸지 않았다. 디스크 적용은 Chrome Reload 완료의 증거가 아니다.
실제 프로필의 확장 설정 페이지 접근은 브라우저 도구 URL 정책이 차단했다.
다른 제어 수단으로 이 차단을 우회하지 않았다.

실제 Chrome 복구 전체 흐름은 **미검증**이다. 소스/격리 worker 성공은 실제 로드된 확장 버전이나
실제 경고 UI의 지원을 입증하지 않는다. 자연 발생한 승인 테스트 경고의 DOM/중지 소속과 전후 ledger가 필요하다.
실제 계정에 오류 UI를 주입하거나 네트워크를 가로채지 않았다. 새 실제 메시지는 이 기록 시점에 보내지 않았다.
기존 테스트 탭은 Chrome 재시작으로 물리적 ID가 바뀌었으며, 재연결 없이 이전 등록을 정상으로 취급하지 않는다.
실제 프로필에 빈 ChatGPT 탭 1개와 `codex_disconnect_test` 격리 그룹만 새로 준비했다.
기존 대화와 그룹은 이동하지 않았다. 새 탭은 아직 작업축에 등록하거나 메시지를 보내지 않았다.

로컬 실제 증거는 ignored `.autopilot/acceptance-evidence/2026-10-21-*`에 보존한다.
개인 Chrome 프로필·인증 자료·실제 계정 원문/trace를 CI 산출물에 포함하지 않는다.
